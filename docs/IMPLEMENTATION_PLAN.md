# DevMoter Calc Engine — 超詳細実装計画書 v1.0

策定日: 2026-11-23  |  ステータス: 設計案・未実装  |  対象: Rust / WASM / DevMoter FAST

## 1. 目的と判断

DevMoter Calc Engineは、Excel系の表計算式を評価する独立Rustライブラリである。DevMoter Officeの軽量XLSX編集を支え、将来は第三者アプリにも組み込めるOSSとする。対象はユーザーが選択した38関数。完全Excel互換は非目標。仕様で宣言したサブセットについて、正確性・安全性・再現性を検証する。

**優先順位:** (1) 正しさ (2) ファイル保全 (3) 互換性 (4) 差分再計算 (5) 性能 (6) AI連携。

**対象外:** VBA、マクロ、ピボット、チャート描画、Power Query、外部ブック参照、全Excel関数、完全なExcel表示互換、Excelの反復計算、外部ネットワークアクセス。

## 2. 技術方針とリポジトリ

- Rust stable、Edition 2024（採用時のツールチェーン互換性をCIで確認）。MSRVは実装開始時に固定し明記。
- リポジトリ案 `devmoter-calc`。ライセンス候補 MIT OR Apache-2.0（依存ライセンス監査後に決定）。
- `crates/calc-core`: 値型、構文解析、セル・ワークブック、依存関係、計算実行器。
- `crates/calc-functions`: 関数登録と各関数群。循環依存を避けるため共通型はcore、関数実装はcoreの公開trait経由で登録する。必要ならcore内のサブモジュールに統合。
- `crates/calc-wasm`: wasm-bindgen境界、JSON/構造化値の転送、メモリ解放。
- `crates/calc-cli`: 開発用の式評価と互換性テスト。
- `tests/fixtures`: 数式、入力、期待値、期待エラー、参照実装とバージョンを記録。
- `benches/`: criterion等による性能回帰測定。WASMは別途ブラウザベンチ。
- `.github/workflows`: fmt、clippy、test、audit、license、fuzz/nightly、WASM smoke。

原則として最初から細かくクレート分割しすぎない。コアのAPI境界が安定してから分割する。

## 3. データモデル

### 3.1 Value

```rust
pub enum Value {
    Blank,
    Number(f64),
    Text(String),
    Boolean(bool),
    Error(CalcError),
    Array(ArrayValue),
}
```

- `Number`はExcel系の浮動小数点演算と整合させる。ただしIEEE 754とExcelの表示・精度規則は同一ではないため、比較試験で差分を明示。
- `Blank`と`Text("")`を区別。セル参照由来の空白、関数引数由来の空白、直接リテラルの型変換は個別に仕様化。
- `ArrayValue`は矩形の行列で、行数・列数・要素数の上限を検証。空配列や次元不一致を定義。
- 日付は初期互換モードではシリアル値を基本とし、ワークブックごとに1900/1904日付系を明示。1900年うるう年互換の特殊挙動をテスト。
- `CalcError`は `#DIV/0!`, `#VALUE!`, `#REF!`, `#NAME?`, `#NUM!`, `#N/A`, `#NULL!`, `#SPILL!`, `#CALC!`, `#CIRC!`（最後は内部表現、表示方針別途）などを型として扱う。Excel互換の表示可否は個別確認。

### 3.2 セル・シート

- `CellId = {sheet_id, row, col}`。内部は0始まり、外部A1表記と分離。
- シート名の引用、`'Sales 2026'!A1`、絶対参照`$A$1`、混合参照`A$1`、範囲`A1:B10`を構文木で表現。
- 数式の原文とAST、評価値、dirty状態、依存先、逆依存先、計算世代を保持。
- 数式のコピー・移動による参照シフトは専用APIに分離。範囲境界超過は`#REF!`。
- 外部ブック参照と構造化テーブル参照は初期非対応として明示的にエラー扱い。黙って無視しない。

## 4. 数式パーサー

1. Lexer: 数値、文字列（`""`エスケープ）、識別子、演算子、括弧、`,`、`:`、`!`、`$`、比較演算子、空白を字句化。
2. Parser: Pratt parserまたは優先順位付き再帰下降。演算子の結合性と優先順位をExcel参照実装で固定。単項マイナス、べき乗、百分率、文字列結合`&`、比較を含む。
3. AST: `Literal`, `Unary`, `Binary`, `Call`, `CellRef`, `RangeRef`, `ArrayLiteral`（後期）。`IF`、`IFERROR`などの遅延評価は評価器の戦略として扱う。
4. エラー: 位置情報（バイトオフセット＋可能なら文字位置）、期待トークン、上限超過を構造化。
5. 安全: 再帰深度、トークン数、式長、ネスト深度を制限。`eval`や任意コード実行は使用しない。

## 5. 評価・再計算・依存関係

- `set_cell`は数式を解析し依存関係を差分更新、変更セルとその逆依存閉包をdirtyにする。
- 再計算は依存順のトポロジカル評価を基本とする。循環参照はSCC（Tarjan/Kosaraju）またはDFSの訪問状態で検出し、明確なエラーとして報告。反復計算は対象外。
- `IF`は条件に従って選択された分岐のみ評価。`IFERROR`は第一引数がエラーのときのみ代替値を評価。`AND`/`OR`の評価規則はExcel互換試験で確認し、一般的なプログラミング言語の短絡評価を無条件に適用しない。
- 依存関係の静的グラフには分岐で参照される可能性のあるセルを登録し、動的依存最適化は後回しにする。
- 計算順序の決定性を担保し、非決定的関数`TODAY`は注入したClockから値を取得。時計の更新時に再評価できるよう揮発性を管理。
- 評価中のセル変更は世代番号またはスナップショットで整合性を確保。WASMのUI操作はバッチ化する。
- `trace(cell)`は参照元、評価した分岐、計算時間、結果・エラーを構造化出力。ただし個人データやセル内容のログはデフォルト無効。

## 6. 38関数の仕様と実装順

**Phase 1: 基本13関数**
- `SUM`: 数値の合計。範囲内の文字列・空白と直接引数の変換規則を区別。
- `AVERAGE`: 数値の平均。対象なしは`#DIV/0!`。
- `MIN`, `MAX`: 数値の極値。対象なしの扱いをExcel互換で確認。
- `COUNT`: 数値の個数。`COUNTA`: 空でない値の個数（空文字列は空白とは異なる）。
- `IF`: 条件と分岐。省略引数の扱いを明示。
- `AND`, `OR`, `NOT`: 真偽判定。配列・空白・文字列の規則を定義。
- `ROUND`: 十進丸めのExcel互換。Rustの`f64::round`だけでは不十分なケースを含むため差分テスト必須。
- `ABS`: 絶対値。`IFERROR`: エラーを捕捉し代替値。

**Phase 2: 条件付き集計・参照6関数**
- `SUMIF`, `SUMIFS`, `COUNTIF`, `COUNTIFS`: 比較演算子付き条件、ワイルドカード`*`/`?`/`~`、文字列・数値条件、複数条件、範囲の形状検証。
- `INDEX`: 配列/参照から位置で取得。初期は配列形式の限定サブセット、参照形式は互換性が確認できるまで非対応。
- `MATCH`: 完全一致と近似一致、昇順/降順の前提条件、検索方向、未発見時`#N/A`。

**Phase 3: 文字列6関数と検索1関数**
- `LEFT`, `RIGHT`, `MID`, `LEN`, `TRIM`, `CONCAT`: UnicodeとExcelの文字数規則（特にUTF-16コード単位、互換性バージョン差）を検証。`TRIM`の空白文字種を明示。
- `XLOOKUP`: 完全一致を最初に実装。未発見時代替、検索方向、近似一致、ワイルドカード、二次元返却は段階的に追加。二分探索モードはソート済み前提を検証・文書化。

**Phase 4: 動的配列3関数**
- `FILTER`: 行・列方向の条件配列、空結果、形状不一致、エラー伝播。
- `SORT`: 安定した並べ替え、昇順/降順、キー列、比較規則、空白・エラー・型混在、元順序の維持。
- `UNIQUE`: 行単位/列単位の重複排除、exactly_onceモード、文字列比較規則。
- 動的配列のスピル範囲を予約し、占有済みセルへの衝突を検出。スピル範囲のリサイズ時に旧出力を適切に解放する。

**Phase 5: 統計・数学・日付9関数**
- `STDEV.S`, `VAR.S`: 標本分散（n-1）、n<2でエラー。数値安定性の高いWelford方式などを検討し、Excel差分を測定。
- `MEDIAN`: 偶数件と奇数件、非数値の扱い。ソート不要の選択アルゴリズムも検討。
- `CORREL`: 対応する数値ペア、ゼロ分散、サイズ不一致、誤差許容値を定義。
- `LOG`: 底省略時10、底0/1/負数の扱い。`EXP`: オーバーフロー。`SQRT`: 負数エラー。
- `TODAY`: Clock注入とタイムゾーン。`DATE`: 年月日の正規化、日付系、境界値。

**総数:** 13+6+7+3+9=38。

## 7. SORTの高速化と計算量

- 汎用比較ソートの下界は`Ω(n log n)`。通常の`SORT`は安定ソートで`O(n log n)`を基準とする。
- 差分SORTはキーと元行IDの組を平衡木などで索引化。初期構築`O(n log n)`、1件の削除・再挿入による**索引更新**は`O(log n)`を目標とする。
- 全件の並べ替え結果を物理的に出力するなら`Ω(n)`が必要。変更位置から後続セルがシフトする場合、結果の更新範囲も大きくなり得る。したがって「SORT全体がO(log n)」とは宣伝しない。
- ランダム値、逆順、整列済み、同値大量、長い文字列、数値/文字列混在、単一セル変更、複数行変更をベンチマークする。
- 先に正確な通常SORTを実装し、差分インデックスは性能測定で有効性を確認してから導入。

## 8. XLSX連携・ファイル保全

- `calc-core`はXLSX ZIP/XMLの読み書きを担当しない。別のadapter層を作る。
- 未編集のシート、書式、グラフ、名前定義、画像、マクロを含むファイルは、読み書きライブラリが保全できると検証できるまで上書き保存しない。
- 原本は保持し、変更差分と新ファイルを別保存。アトミック書き込み、チェックサム、バックアップ、キャンセルを用意。
- Excel数式キャッシュは式と計算値の整合を確認。未対応式のキャッシュを誤って上書きしない。
- 保存後に再オープンし、構造比較・未編集部の差分・計算結果を検査する。

## 9. 公開API案

```rust
pub struct CalcEngine { /* private */ }

impl CalcEngine {
    pub fn new(config: EngineConfig) -> Self;
    pub fn set_cell(&mut self, sheet: &str, address: &str, input: CellInput) -> Result<(), CalcError>;
    pub fn get_value(&mut self, sheet: &str, address: &str) -> Result<Value, CalcError>;
```

### 10.2 代表的なゴールデンテスト

| 式 | 期待値/条件 |
|---|---|
| `=1+2*3` | `7` |
| `=SUM(1,2,3)` | `6` |
| `=IF(FALSE,1/0,42)` | `42`、未使用分岐は評価しない |
| `=IFERROR(1/0,99)` | `99` |
| `=LEFT("沖縄県",2)` | `"沖縄"` |
| `=SQRT(-1)` | `#NUM!` |
| `=STDEV.S(1)` | `#DIV/0!` |
| `=CORREL(A1:A3,B1:B2)` | `#N/A`（参照先の内容に依存しないサイズ不一致の検査） |
| `=SORT(A1:A100)` | 安定した昇順、入力を変更しない |
| `=UNIQUE(A1:A100)` | 最初の出現順を維持 |

`ROUND(2.345,2)`のような浮動小数点境界は参照実装との比較で仕様を固定し、実装言語の標準丸めを期待値の唯一の根拠にしない。

### 10.3 性質ベース試験

- `SUM`の結果は、数値だけからなる有限配列の順序を変えても許容誤差内で一致（浮動小数点の結合則を厳密等号で仮定しない）。
- `SORT`は入力と同じ要素の多重集合を保持し、比較器に従って単調。
- `UNIQUE`の結果には重複がなく、入力に含まれない値を生成しない。
- `FILTER`の結果行は元入力の相対順を維持。
- 変更セルに依存しない数式は、差分再計算でも値が変わらない。
- 同じ入力と同じClockでネイティブ/WASMが同一結果。

### 10.4 ファズ試験・セキュリティ

- 任意のUTF-8、巨大な括弧列、深いネスト、長いシート名、巨大範囲、循環参照を入力。
- panic、無限ループ、メモリ枯渇、指数的展開を防ぐ。
- 入力上限（初期提案）: 式長64 KiB、構文木ノード10,000、再帰深度256、評価ステップ100万、動的配列100万セル。実測で調整し、設定可能な上限とする。
- 計算時間の予算、キャンセル、ワークブック単位のメモリ予算を導入。
- 数式文字列を外部コマンド・ファイル・HTTPに渡さない。計算コアにネットワーク権限を与えない。

### 10.5 互換性オラクル

- Excelデスクトップ、Excel Web、LibreOfficeを可能な範囲で参照。バージョン、OS、ロケール、日付系、数式、入力、期待値をフィクスチャに記録。
- 互換性差分は「エンジンのバグ」「仕様上の未対応」「参照実装間の差」「許容される浮動小数点差」に分類。
- `XLOOKUP`、動的配列、文字列長、日付、条件付き集計を重点比較。
- 参照実装をCIで利用できない場合は検証済みフィクスチャをコミットし、生成手順と出典を記録。

## 11. 性能計画

- データ規模: 1千、1万、10万、100万セル。性能測定は入力分布と依存関係密度を固定。
- シナリオ: 初回解析、初回計算、単一セル変更、1%変更、全セル変更、SORT初回、SORT差分、FILTER/UNIQUE、WASM起動、メモリピーク。
- 指標: p50/p95遅延、セル/秒、RSS、WASM線形メモリ、GC/境界コスト、ビルドサイズ。
- 数値目標はベースライン計測後に決定。根拠なく「100万セルを何ms」と約束しない。
- ARM64 Chromebook環境を実機性能検証の重要ターゲットにする。CIのx86-64結果をARM64実測と混同しない。
