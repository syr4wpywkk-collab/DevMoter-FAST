## Delivery integrity (Issue #32)

There is no generally reliable way to tell whether a provider accepted a prompt when the network or process fails before acknowledgment. Automatically retrying an ambiguous send can execute a task twice.

The queue now follows:

1. Persist `pending → dispatching` before calling the agent.
2. On positive acknowledgment, remove the item and persist a history event.
3. On failure or restart with an in-flight item, quarantine as `needs-review`.
4. Never auto-dispatch `needs-review`. Show a warning and require the owner to inspect the target session before explicitly retrying.

The user can still edit or cancel a quarantined item; a currently dispatching item is locked from misleading edits/cancellation. Queue state remains local to DevMoter's private host.

## Safety limits (Issue #34)

The remaining budget is now assigned to a newly created destination session **before** `turn/start` (Codex) or `/prompt` (OpenCode). If inheritance reports a depleted budget, the first turn is blocked, rather than running once without the restriction. Existing per-host observation-based reconciliation remains best-effort, and this is **not** a hard billing cap or shared distributed token ledger.

## Scratch workspace lifetime (Issue #38)

Previously, the side-conversation creation path unregistered its scratch project in a `finally` block immediately after starting the agent. An active session could therefore lose its registered project reference. Now only incomplete setup attempts clean up automatically; started side sessions keep their scratch project registered. Scratch directories and registrations require an explicit, separate cleanup decision from the owner.
