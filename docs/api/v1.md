# 統合 REST API v1

4エンジンを同じ形の API で操作するための入口。SQL の方言やデータ型はエンジンのものをそのまま通す（共通化するのはリクエストとレスポンスの形だけ）。

4エンジンすべてにアダプターがある。SQLite・DuckDB・PostgreSQL は SQL（`/query`）、Valkey はコマンド（`/command`）で操作する。

## 利用範囲（重要）

ユーザー認証（機能 #21）と権限管理（#22）がまだ無いため、ローカル検証専用。API キー（#24）を有効にしても同じ（キーは呼び出し元を識別するだけで、キーごとの権限はまだ無い）。

- `server.host` はループバック（`127.0.0.1`、`::1`、`localhost`）以外を指定すると起動しない。
- `Host` ヘッダーがこのマシンを指していないリクエストは 403（DNS リバインディング対策）。
- `Origin` ヘッダー付き、または `Sec-Fetch-Site` が `none` 以外のリクエストは 403（Web ページからの呼び出しを拒否）。CORS ヘッダーは返さない。
- API キーを設定しない場合、同じマシン上の他のプロセス・他のユーザーから呼び出せる。信頼できないユーザーがいるマシンでは、キーを有効にするか、起動しないこと。

## 起動

```sh
npm run build:engines -- sqlite          # または npm run build:engines:container -- sqlite
cp devmoter-base.config.example.json devmoter-base.config.json
mkdir -p data
npm start
```

| 環境変数 | 意味 | 既定値 |
|---|---|---|
| `DEVMOTER_BASE_CONFIG` | 設定ファイル | `./devmoter-base.config.json` |
| `DEVMOTER_BASE_ENGINES_DIR` | ビルド済みエンジンの場所 | `./build/<アーキテクチャ>` |
| `DEVMOTER_BASE_LOG_LEVEL` | ログレベル | `info` |

設定ファイルの `databases[].file` が相対パスのときは、設定ファイルのあるディレクトリが基準。`readOnly: true` のデータベースは書き込みを拒否する。

## エンドポイント

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/v1/health` | API プロセスの生存確認 |
| GET | `/v1/health/engines` | 設定済みデータベースごとのエンジンのヘルスチェック。1つでも応答しなければ 503 |
| GET | `/v1/databases` | 設定済みデータベースの一覧 |
| GET | `/v1/databases/:name` | データベース1件 |
| GET | `/v1/databases/:name/health` | データベース1件のヘルスチェック。応答しなければ 503 |
| POST | `/v1/databases/:name/query` | SQL の実行（SQLite・DuckDB・PostgreSQL） |
| POST | `/v1/databases/:name/command` | コマンドの実行（Valkey） |

### ヘルスチェック

クエリと同じ経路でエンジンにバージョンを問い合わせる（制限時間 5 秒）。エンジンが未ビルド、データベースファイルが開けない、応答が無い場合は `unavailable` と理由を返す。`/v1/health` は API プロセス自体の生存確認で、エンジンには触れない。

```json
{
  "status": "degraded",
  "databases": [
    { "name": "app", "engine": "sqlite", "status": "ok", "version": "3.55.0", "latencyMs": 4 },
    { "name": "analytics", "engine": "duckdb", "status": "unavailable", "latencyMs": 2, "message": "the duckdb engine is not built; run \"npm run build:engines -- duckdb\"" }
  ]
}
```

### POST /v1/databases/:name/query

```sh
curl -s http://127.0.0.1:8787/v1/databases/app/query \
  -H 'Content-Type: application/json' \
  -d '{"sql": "SELECT id, body FROM notes WHERE id = ?1", "params": [1]}'
```

リクエスト:

| フィールド | 型 | 内容 |
|---|---|---|
| `sql` | string | 必須。複数の文を `;` で区切って送れる |
| `params` | array | 位置パラメーター（SQLite は `?` / `?1`、DuckDB は `?` / `$1`）。`null`、真偽値、数値、文字列、バイナリは `{"$base64": "..."}` |
| `timeoutMs` | number | 1〜300000。既定は 30000 |

レスポンス（200）:

```json
{
  "database": "app",
  "engine": "sqlite",
  "results": [{ "columns": ["id", "body"], "rows": [{ "id": 1, "body": "hello" }], "rowCount": 1 }],
  "durationMs": 4
}
```

`results` は、行を返した文ごとに1要素。

### エラー

すべて同じ形: `{"error": {"code": "...", "message": "...", "requestId": "..."}}`。`requestId` はレスポンスの `X-Request-Id` と同じ値で、サーバーのログと突き合わせられる。

| HTTP | code | 意味 |
|---|---|---|
| 400 | `invalid_json` / `invalid_request` | リクエストの形が不正 |
| 400 | `unsupported_operation` | SQL データベースに `/command`、Valkey に `/query` を送った |
| 401 | `unauthorized` | API キーが無い、形式が違う、存在しない、失効済み |
| 403 | `forbidden_host` / `cross_origin_forbidden` | 上記「利用範囲」の拒否 |
| 403 | `command_not_allowed` | API から実行できない Valkey コマンド、または読み取り専用データベースへの書き込みコマンド |
| 404 | `not_found` / `database_not_found` | |
| 405 | `method_not_allowed` | |
| 413 | `body_too_large` | リクエスト本文が 1 MiB を超えた |
| 415 | `unsupported_media_type` | `Content-Type: application/json` でない |
| 422 | `query_failed` | エンジンが SQL を拒否した。`message` はエンジンのメッセージ |
| 422 | `result_too_large` | 結果が 32 MiB を超えた |
| 429 | `too_many_requests` | 同時実行数（8）を超えた |
| 503 | `engine_unavailable` | エンジンがビルドされていない、またはサーバーに接続できない |
| 504 | `timeout` | 制限時間内に終わらなかった（クエリは強制終了される） |

ログには SQL・パラメーター・コマンド・結果を出力しない（メソッド、ルート、データベース名、ステータス、所要時間、行数のみ）。

## SQLite アダプターの仕様と制限

`engines/sqlite` からビルドした `sqlite3` シェルを、リクエストごとに1プロセス起動して実行する（エンジンのコードは変更していない）。

安全性:

- シェルはセーフモード（`-safe`）で動く。`ATTACH`、`VACUUM INTO`、`load_extension()`、`readfile()`、`writefile()`、ファイルやプログラムに触れるドットコマンドは拒否されるので、クエリが届くのは設定したデータベースファイル1つだけ。
- パラメーターの値は16進表記で渡すので、値の中の文字が SQL として解釈されることはない。
- エンジンのプロセスには API サーバーの環境変数を渡さない。
- SQL とパラメーターはシェルの標準入力で渡す。プログラム引数には載せないので、同じマシンの他のユーザーがプロセス一覧（`ps`）から読むことはできない。

制限（接続プール #16 を実装するまで）:

- 接続状態（`PRAGMA` の設定、一時テーブル、トランザクション）はリクエストをまたがない。トランザクションは `BEGIN; ...; COMMIT;` を1リクエストで送る。途中の文が失敗すると全体がロールバックされ、エラーだけが返る。
- SQL は 64 KiB まで、パラメーターは 999 個まで・エンコード後 96 KiB まで。
- 行を返さなかった文は `results` に現れない（SQLite のシェルは0行のとき列名も出力しない）。
- 絶対値が 2^53 − 1 を超える整数は、丸めずに文字列で返す。
- リクエストの JSON に、絶対値が 2^53 − 1（9007199254740991）を超える整数を数値として書くと `400 invalid_request` になる。小数点や指数を付けた書き方（`9007199254740993.0`、`1e20`）も同じ（JSON の数値は倍精度で読まれ、黙って丸められるため）。文字列で送り、必要なら SQL 側で `CAST(?1 AS INTEGER)` する。
- SQL の行を `.` で始めることはできない（`400 invalid_request`）。シェルがドットコマンドとして読むため。行頭に空白を入れるか、その文字列をパラメーターで渡す。
- `VACUUM` は使えない（セーフモードが内部の `ATTACH` を拒否する）。`VACUUM INTO` も同じ。
- NUL 文字（`char(0)`）を含む TEXT は NUL の手前までしか返らない。バイナリは BLOB にして `hex(col)` で取得する。
- BLOB 列はそのままでは正しく返らない。`hex(col)` などで文字列にして取得する。
- 同名の列が複数あると最後の1つだけが残る。`AS` で別名を付ける。
- SQL に書いたパラメーターのうち `params` に値が無いものは `NULL` になる。
- 名前付きパラメーター（`:name`）は未対応。

## DuckDB アダプターの仕様と制限

`engines/duckdb` からビルドした `duckdb` シェルを、SQLite と同じくリクエストごとに1プロセス起動して実行する。

安全性:

- シェルはセーフモード（`-safe`）で動く。設定はロックされ、データベース外のファイル操作（`ATTACH`、`COPY`、`read_csv()` などのファイル読み込み、`EXPORT`、`INSTALL`/`LOAD`）と `getenv()` は拒否される。このため CSV・Parquet ファイルの分析（機能 #46）はまだこの API から使えない。
- パラメーターの値は16進表記で渡す。
- SQL とパラメーターはシェルの標準入力で渡す（SQLite と同じ。プロセス一覧からは読めない）。

制限:

- 接続状態はリクエストをまたがない（SQLite と同じ）。
- `params` を付けるときは文を1つだけ送る（内部で `PREPARE` / `EXECUTE` に変換するため）。2つ以上の文は `400 invalid_request` になり、何も実行されない。値の無いパラメーターはエラーになる。
- `EXPLAIN` は単独の文として、`params` なしで送る。結果は `plan` 列1つ・1行で、値は DuckDB が出力した実行計画の文字列（`EXPLAIN (FORMAT JSON)` なら JSON 文字列）。
- SQL の行を `.` で始めることはできない（`400 invalid_request`。SQLite と同じ）。
- SQL は 64 KiB まで、パラメーターは 999 個まで・エンコード後 48 KiB まで。文字列パラメーターに NUL 文字は使えない。
- 行を返さない文（DDL、`RETURNING` の無い `INSERT` など）は `results` に現れない。0行の `SELECT` は列名の無い空の結果になる。
- ±2^53 を超える整数は文字列、`Infinity`・`-Infinity`・`NaN` は文字列で返す。`HUGEINT`・`DECIMAL`・日付時刻は DuckDB の JSON 出力のとおり文字列。BLOB は `hex(col)` などで取得する。
- 同時に書き込めるプロセスは1つ。書き込み中の別リクエストはロックエラー（422）になる。
- メモリとスレッド数は DuckDB の既定値（プロセスごと）。

## API キー（機能 #24）

設定ファイルに `auth` を書くと、`/v1/health` 以外のすべてのエンドポイントで API キーが必要になる。

```json
{ "auth": { "keysFile": "data/api-keys.json" }, "audit": { "file": "data/audit.log" } }
```

```sh
npm run keys -- create "FAST agent"   # キーを発行。キーそのものはこの1回だけ表示される
npm run keys -- list                  # ID・名前・発行日時・失効日時（キーそのものは出ない）
npm run keys -- revoke <id>           # 失効。起動中のサーバーにも再起動なしで反映される

curl -s http://127.0.0.1:8787/v1/databases -H 'Authorization: Bearer dmb_<id>_<secret>'
```

- キーの形式は `dmb_<ID 12桁>_<秘密の部分 43文字>`。ID は公開してよい識別子で、ログと監査ログに出る。
- キーファイルには秘密の部分の SHA-256 だけを保存する（権限 600）。発行後にキーを再表示する方法は無い。失くしたら失効して再発行する。
- キーが無い・形式が違う・存在しない・失効済みは、どれも 401 `unauthorized`。エンジンには到達しない。
- 発行と失効は、キーファイルのロックを取って1件ずつ反映する。サーバーの起動中や、複数のコマンドを同時に実行しても、ほかの発行・失効を打ち消さない。
- 監査ログを設定している場合、発行の記録を書けなければキーは発行されない（作ったキーは失効され、表示されない。終了コード 1）。
- 発行と失効はコマンドラインだけで行う（API には無い）。役割の区別がまだ無いので、API に置くとキーを持つ誰もが新しいキーを発行できてしまうため。
- 制限: キーごとの権限・データベース単位の制御（#22、#23）、有効期限、試行回数の制限（#27）はまだ無い。キーは全データベースに対する全操作を許可する。このためキーを有効にしても `server.host` はループバック限定のまま。

## 操作監査ログ（機能 #26）

設定ファイルに `audit` を書くと、`/v1/health` 以外のすべてのリクエストと、キーの発行・失効、サーバーの起動を1行1件の JSON で記録する（追記のみ。権限は書き込みのたびに 600 にする。既存のファイルも同じ）。

```json
{"time":"2026-11-24T00:00:00.000Z","event":"api.request","requestId":"…","method":"POST","keyId":"3f9c2a1b7d4e","route":"databases.query","database":"app","engine":"sqlite","operation":"INSERT","rows":0,"status":200,"durationMs":12,"prev":"…"}
```

| フィールド | 内容 |
|---|---|
| `event` | `api.request`、`auth.failed`（`reason`: `missing` / `malformed` / `unknown` / `revoked`）、`key.created`、`key.revoked`、`server.started` |
| `keyId` | 操作したキーの ID（キーを設定していない場合は無い） |
| `database` / `engine` | 対象のデータベース名とエンジン（1つのデータベースを対象にするリクエスト: 詳細、ヘルスチェック、`query`、`command`。存在しない名前のときは無い） |
| `operation` | 操作の種類だけ: SQL の最初の文の先頭のキーワード（`SELECT`、`INSERT`、…。文を始めるキーワードでない語は `OTHER`）か Valkey のコマンド名 |
| `status` / `error` | HTTP ステータスとエラーコード |
| `prev` | 直前の行の SHA-256。行の書き換え・途中の削除があると鎖が切れる |

- SQL の本文、パラメーター、コマンドの引数、結果、キーの秘密の部分は記録しない。
- レスポンスを返す前に記録する。記録に失敗した場合、リクエストには応答し、失敗をエラーログに出す。起動時に書き込めなければサーバーは起動しない。
- `npm run audit:verify` が鎖を検査し、切れている行を報告する。末尾の行の削除と、ファイル全体の作り直しは検出できない（外部への転送は今後の機能）。
- ローテーションはまだ無い。

## PostgreSQL・Valkey への接続（共通）

PostgreSQL と Valkey はサーバーなので、アダプターはエンジンを起動せず、すでに動いているサーバーに接続する。

- 接続先は Unix ソケットかループバックアドレスだけ。他のマシンへの接続（TLS を含む）は未対応で、設定すると起動しない。
- パスワードは設定ファイルに書けない。`passwordEnv` に環境変数の名前を書き、値は環境変数で渡す（秘密情報の安全な保存 #25 を実装するまでの扱い）。
- リクエストごとに1接続を使う（接続プール #16 を実装するまで）。接続状態はリクエストをまたがない。

```json
{ "name": "main", "engine": "postgresql", "host": "/run/postgresql", "port": 5432, "database": "app", "user": "app", "passwordEnv": "DMB_PG_PASSWORD" }
{ "name": "cache", "engine": "valkey", "socketPath": "/run/valkey/valkey.sock", "db": 0 }
```

PostgreSQL の `host` は、ソケットのあるディレクトリの絶対パスかループバックのホスト名。Valkey は `socketPath` か `host`（+ `port`）のどちらか一方。

## PostgreSQL アダプターの仕様と制限

- クライアントは npm の `pg`（バージョン固定）。パラメーター（`$1`、`$2`、…）は拡張問い合わせプロトコルで SQL とは別に送るので、値が SQL として解釈されることはない。
- `params` を付けるときは文を1つだけ送る。付けなければ複数の文を送れる。
- 制限時間を過ぎるか、クライアントが切断すると、サーバー側のクエリもキャンセルする。`statement_timeout` も同じ値に設定する。
- 値の変換: `boolean`、`int2`/`int4`、`float4`/`float8`、`json`/`jsonb` だけを JSON の型に変換する。それ以外（`bigint`、`numeric`、日付時刻、配列、`bytea`（`\x…` 形式）など）は PostgreSQL が返した文字列のまま返すので、丸めやタイムゾーン変換は起きない。`NaN`・`Infinity` は文字列。
- `json`/`jsonb` の中の数値は、JavaScript の数値で正確に表せるものだけを数値で返す。桁数の多い小数、±2^53 を超える整数、範囲外の値（`1e400` など）は PostgreSQL が返した表記の文字列になる。
- `COPY ... TO STDOUT` と `COPY ... FROM STDIN` は使えない。SQL の文面で判定し、サーバーへ送る前に `400 invalid_request` で拒否するので、`COPY (INSERT ... RETURNING ...) TO STDOUT` のような書き込みも実行されない。行の取得は `SELECT`、投入は `INSERT` を使う。
- 数値パラメーターのうち ±2^53 を超える整数は文字列で送る（`"9007199254740993"`）。数値のままでは 400 になる。
- 列を返さない文（DDL、`RETURNING` の無い `INSERT` など）は `results` に現れない。0行の `SELECT` は列名付きの空の結果になる。
- エラーの `message` には SQLSTATE が付く（例: `column "nope" does not exist (SQLSTATE 42703)`）。接続・認証の失敗は 503。
- 結果は 32 MiB まで、SQL は 1 MiB まで。
- `readOnly: true` は各トランザクションを読み取り専用で開始するだけで、クエリ側で解除できる（誤操作の防止用）。強制するには、書き込み権限の無いロールで接続する。

## Valkey アダプターの仕様と制限

```sh
curl -s http://127.0.0.1:8787/v1/databases/cache/command \
  -H 'Content-Type: application/json' \
  -d '{"command": ["SET", "greeting", "hello", "EX", 60]}'
```

| フィールド | 型 | 内容 |
|---|---|---|
| `command` | array | 必須。コマンド名と引数。引数は文字列、数値、バイナリは `{"$base64": "..."}` |
| `timeoutMs` | number | 1〜300000。既定は 30000 |

レスポンス（200）: `{"database": "cache", "engine": "valkey", "result": "OK", "durationMs": 1}`

- 1リクエストで1コマンド。引数は長さ付きで送るので、値がコマンドとして解釈されることはない。
- 応答（RESP3）と JSON の対応: 文字列は文字列（UTF-8 として不正なバイト列は `{"$base64": "..."}`）、整数・小数は数値（±2^53 を超える整数は文字列、`inf`・`nan` は文字列）、配列・セットは配列、マップ（`HGETALL` など）はオブジェクト、nil は `null`。
- 実行できるコマンドは、サーバー自身が返すコマンド情報（`COMMAND INFO` のフラグと ACL カテゴリ）で判定する。権限管理（#22、#28）を実装するまで、次のカテゴリは拒否する（403 `command_not_allowed`）:
  - `@admin`（`CONFIG`、`SHUTDOWN`、`DEBUG`、`ACL`、`REPLICAOF` など）
  - `@dangerous`（`FLUSHALL`、`FLUSHDB`、`KEYS`、`INFO`、`MIGRATE` など。キーの列挙は `SCAN`、削除は `DEL`/`UNLINK` を使う）
  - `@scripting`（`EVAL`、`FUNCTION` など）、`@pubsub`（`SUBSCRIBE`、`PUBLISH` など）
  - `@transaction`（`MULTI` など）と `@connection`（`SELECT`、`AUTH` など）: リクエストごとに接続が変わるため意味を持たない。`PING` と `ECHO` は使える。論理データベースは設定の `db` で選ぶ。
  - ほかの論理データベースを指すコマンド（`MOVE`、`DB` オプション付きの `COPY`）: データベースのエントリーが届くのは、設定した論理データベース1つだけ。
- `readOnly: true` のデータベースでは、サーバーが読み取り専用と分類するコマンドだけを実行できる。
- 数値の引数のうち ±2^53 を超える整数は文字列で送る。数値のままでは 400 になる。
- 接続ユーザーには `COMMAND INFO` の実行権限が必要（ACL で `+command|info`）。無いとヘルスチェックは `unavailable` になる。
- コマンドは 1 MiB・4096 引数まで、応答は 32 MiB まで。
